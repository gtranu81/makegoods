# 당신의 창업을 응원합니다

제주 굿즈 스타트업 도전을 위한 초등학생·교사 웹앱입니다. 모둠별 의뢰서, 교사 검토 후 결과 전달, 의뢰서 피드백, 코인과 프로젝트 누적 기록을 제공합니다.

## 설치 없이 체험하기

`dist/jeju-startup-demo.html`을 다운로드해 Chrome 또는 Edge에서 열면 됩니다. 압축 파일을 받은 경우 먼저 압축을 풀어 주세요. API 키나 Node 설치가 필요하지 않습니다.

1. 상단 **① 학생 체험**에서 의뢰서를 작성해 제출합니다.
2. **② 교사 체험**으로 전환해 의뢰서를 열고 후보 3개를 작성합니다.
3. 후보를 선택하고 검토 확인 후 전송합니다.
4. **① 학생 체험**으로 돌아가 전달된 결과를 확인합니다.

브라우저에 체험 데이터만 저장합니다. 다른 기기·브라우저와 공유되지 않으며, 브라우저 설정에 따라 파일 저장이 유지되지 않을 수 있습니다. 실제 AI·서버 인증·이미지 생성·다중 사용자 접속을 제공하지 않는 별도의 오프라인 데모입니다. 실제 개인정보와 실제 비밀번호는 입력하지 마세요. **처음부터** 버튼으로 지울 수 있습니다.

체험 계정: 교사 `teacher` / `DemoTeacher2026`, 학생 `group01` / `DemoStudent2026`. 상단 버튼으로 비밀번호 입력 없이 전환할 수 있습니다. 서버 앱에는 이 계정을 생성하지 않습니다.

원본 화면이 바뀌면 `npm run demo:build`로 단일 HTML을 다시 생성합니다. 화면과 CSS는 실제 앱에서 가져오고, 데이터 처리만 `demo/runtime.js`의 브라우저용 시뮬레이션을 사용합니다.

## 시작하기

Node.js **24.5 이상**이 필요합니다. 별도의 npm 런타임 의존성이나 데이터베이스 서버는 필요하지 않습니다. Node의 SQLite를 사용합니다.

```sh
cd /workspace/makegoods
npm ci
npm start
```

서버 기본 포트는 3000입니다. 브라우저에서 서버 주소를 열면 첫 교사 계정을 생성하는 화면이 나옵니다. 기본 관리자 비밀번호는 없습니다. 첫 교사 계정은 최초 한 번만 생성할 수 있습니다.

1. 교사 이름, 아이디, 10자 이상의 비밀번호로 관리자 계정을 만듭니다.
2. 교사로 로그인하고 **모둠 · 계정 관리 → 모둠 계정 추가**에서 학생 모둠 계정을 만듭니다.
3. 학생은 **컨설팅 분야 → 세부 활동**을 고르고 예시를 참고해 질문 3개에 자신의 생각을 적습니다. 별도 제목·프롬프트·결과 형식 입력은 필요 없습니다. **컨설팅 의뢰하기**를 누를 때 코인 1개를 사용합니다.
4. 교사는 **의뢰서 검토**에서 활동별 후보 3개를 작성하고, 내용·평가를 수정해 검토 확인 후 선택한 결과만 전달합니다.
5. 학생은 전달받은 글·표·이미지를 보고 **이 결과 수정 의뢰하기**로 이전 결과를 고른 뒤 수정할 점·바꿀 방법·유지할 점을 적습니다. 이전 결과는 보존하며 새 의뢰에 연결합니다.
6. **프로젝트 기록**에서 모둠·상태·날짜로 필터링하고 의뢰서·전달 결과·평가를 출력할 수 있습니다.

### 세부 활동과 학생 질문

초등학교 4~6학년용으로 모든 활동에 핵심 질문 3개와 질문 아래 답변 예시를 표시합니다.

| 분야 | 세부 활동 | 결과물 |
| --- | --- | --- |
| 창업 아이디어 | A1 새로운 굿즈 추천받기 | 굿즈 3개, 특징·용도·제주 요소, 가장 추천하는 안과 이유 |
| 창업 아이디어 | A2 내 아이디어 발전시키기 | 좋은 점, 발전 방법 3가지, 발전된 모습과 특징 |
| 시장 조사 | B1 수출할 나라 추천받기 | 국가 3개, 문화·생활 특징, 추천 이유 |
| 시장 조사 | B2 수출할 나라 알아보기 | 문화·생활, 예상 소비자, 어울리는 점, 수출 고려 사항 |
| 굿즈 디자인 | C1 굿즈 디자인 시안 만들기 | 실제 이미지, 주요 특징, 제주 요소와 요청 반영 내용 |
| 아이디어 수정 | D1 이전 컨설팅 결과 수정하기 | 선택한 결과의 수정본, 변경 내용과 차이, 디자인이면 수정 이미지 |
| 홍보·마케팅 | E1 홍보 문구 만들기 | 문구 3개, 추천 이유, 현지 언어와 한국어 뜻 |
| 홍보·마케팅 | E2 홍보 방법 추천받기 | 홍보 아이디어 3개, 구체적인 실행 방법, 추천 이유 |

AI에는 활동·질문·답변·필요한 결과 형식을 함께 전달합니다. 초등학교 4학년도 이해할 수 있는 표현, 학생의 용도·핵심 기능 우선, 입력하지 않은 조건은 제안으로 구분, 시장 정보의 확인된 사실·AI 추정·제안 구분을 지시합니다. 언어나 국가가 지정되지 않으면 임의로 확정하지 않습니다. 출처와 사실 여부는 교사가 검토해야 합니다.

새 디자인 의뢰와 디자인 수정 의뢰는 교사의 **후보 3개 작성** 시 실제 AI 이미지 3개도 생성합니다. 별도 이미지 API 비용과 모델 권한이 필요하며 실행 전에 화면에서 확인합니다. 디자인 수정 시 이전에 전달된 이미지가 있으면 해당 이미지를 편집 API에 전달하고, 이전 결과·수정 요청·유지할 특징을 함께 참조합니다. 반복 수정에서도 원래 컨설팅의 종류를 유지합니다. 이미지 실패 시 설명은 검토 상태로 남고 오류를 표시합니다. 각 후보의 이미지 생성으로 재시도하거나 교사 직접 첨부를 사용할 수 있습니다. 새 AI 디자인 결과는 선택한 후보의 이미지가 준비돼야 전송할 수 있습니다.

디자인 의뢰(디자인 수정 포함)의 **교사 직접 작성 · 이미지 첨부**에서는 AI 없이 제목·요약·내용과 선택 이미지(PNG/JPEG/WebP, 최대 5MB)를 전달할 수 있습니다. 학생 코인은 추가 차감하지 않습니다.

기존 공통 질문으로 작성한 의뢰와 결과는 변경 없이 표시하며 계속 검토·전송할 수 있습니다. SQLite 스키마 변경이나 기존 데이터 초기화는 필요하지 않습니다. 체험 모드와 오프라인 데모는 활동에 맞춘 설명 예시만 제공하며 실제 AI 분석·이미지 생성은 하지 않습니다.

## AI 연결

`npm start`는 `--use-env-proxy`를 사용해 클라우드의 HTTPS 프록시·인증 경로를 유지합니다.

키가 없으면 **체험 모드**가 명확히 표시됩니다. 체험 후보와 점수는 동작 확인용 예시이며 실제 AI 분석이나 학습 성취도 평가가 아닙니다.

실제 후보 작성을 사용하려면 서버의 환경 변수로 다음을 설정하고 재시작합니다. API 키는 브라우저·학생 의뢰서·Git 저장소에 넣지 마세요. `.env` 자동 로딩은 하지 않습니다. 호스팅 서비스의 환경 변수 설정 또는 쉘 환경을 사용하세요.

| 변수 | 용도 | 기본값 |
| --- | --- | --- |
| AI_API_KEY | OpenAI API 키, 서버에서만 사용 | 없음: 체험 모드 |
| AI_IMAGE_MODEL | 디자인 시안 이미지 모델 | gpt-image-1.5 |
| AI_MODEL | 텍스트 후보·평가 모델 | gpt-4.1-mini |
| PORT | 서버 포트 | 3000 |
| HOST | 수신 인터페이스 | 0.0.0.0 |
| DB_PATH | SQLite 파일 경로 | data/app.sqlite |
| NODE_ENV | 배포에서는 production으로 설정 | 미설정 |
| APP_ORIGIN | 외부 주소, 예: https://your-app.example.com (마지막 / 제외) | Render 외부 주소 또는 로컬 http 호스트 |
| SETUP_TOKEN | 최초 교사 계정 생성용 비밀 코드. production에서 필수 | 로컬 개발은 선택 |

AI 후보는 서로 다른 제안 3개와 목표·배경·구체성·결과 형식·안전성에 대한 총 20점 평가를 포함합니다. 교사는 후보 내용과 평가를 수정할 수 있습니다. 새 디자인 컨설팅과 디자인 수정 의뢰는 **설명과 실제 디자인 이미지**를 함께 생성합니다. 기존 양식의 디자인 의뢰와 이미지 재시도는 후보별 **시안 이미지 생성** 버튼을 사용합니다. 이미지 모델 권한과 별도 API 비용이 필요합니다. 후보 재생성 시 기존 이미지 연결을 초기화하고 새 활동의 디자인 이미지는 다시 생성합니다. 이미지 생성은 서버에서 저장된 후보 내용을 사용합니다. 교사가 수정 중인 텍스트는 결과 전송 시 저장되므로 이미지 생성 전에 이 점을 확인하세요.

AI 호출은 교사가 후보 작성 또는 이미지 생성 버튼을 눌렀을 때 일어납니다. 실패 시 오류를 표시하며 체험 결과로 조용히 대체하지 않습니다. 교사의 재생성은 학생 코인을 추가 차감하지 않지만 API 비용은 발생할 수 있습니다. AI_API_KEY가 설정되어 있다는 표시만으로 API 정상 작동을 보증하지 않습니다.

전송 내용은 선택한 활동과 질문 3개의 답변입니다. 수정 의뢰에서는 해당 모둠에 전달된 이전 의뢰·선택 결과·교사 피드백을 함께 전송하고, 이미지 수정에는 이전에 전달된 이미지를 사용합니다. 계정 비밀번호는 AI에 보내지 않습니다. 의뢰서에 개인정보가 들어 있으면 외부 서비스로 전송될 수 있으므로 교사가 먼저 확인하세요. 자동 프롬프트만으로 문화 편향·저작권·사실 오류를 완전히 막을 수 없으므로 전송 전 교사 검토를 필수로 두었습니다. 데이터 보관·사용 정책은 사용하는 AI 서비스의 현재 조건을 확인하세요.

## 코인 규칙

- 기본은 모둠별 하루 3개입니다. 한국 시간(Asia/Seoul)으로 날짜가 바뀐 후 다음 접속·제출 때 하루 한도로 초기화됩니다. 미사용 코인은 이월되지 않습니다.
- 프로젝트 기간 전체 모드는 매일 초기화하지 않습니다. 기간의 시작/종료 날짜 자동 처리는 없고 교사가 기간 한도를 설정하고 종료 시 계정을 중지합니다.
- 교사가 즉시 코인을 추가하거나 삭감할 수 있고 이유가 원장에 기록됩니다. 하루 모드의 추가분은 당일 잔액에만 적용됩니다.
- 하루 기본 한도 변경은 다음 날부터 적용됩니다. 운영 방식 또는 기간 전체 한도를 변경하면 잔액이 새 한도로 초기화됩니다.
- 추가 요청도 코인 1개를 사용합니다. 동시에 제출해도 잔액 아래로 차감되지 않도록 트랜잭션을 사용합니다.
- 학생이 화면에서 보는 코인은 학습 활동 제한용이며 AI 서비스의 API 토큰·결제 금액과 무관합니다.

## Render에서 웹으로 AI 체험하기

배포 버튼: https://render.com/deploy?repo=https://github.com/gtranu81/makegoods

1. Render 계정을 만들거나 로그인합니다. GitHub 저장소 접근 권한을 요청하면 `gtranu81/makegoods`를 연결합니다. 비공개 저장소가 배포 버튼으로 열리지 않으면 Render 대시보드에서 **New → Blueprint**로 해당 저장소를 선택합니다.
2. 이 저장소의 `render.yaml`을 사용합니다. **Starter 웹 서비스와 1GB 영구 디스크에는 요금이 발생합니다.** 화면의 요금을 확인하고 배포합니다. 무료 임시 디스크는 학생 기록 보존에 적합하지 않으므로 기본 구성으로 사용하지 않습니다.
3. `AI_API_KEY` 입력란에 본인의 OpenAI API 키를 입력합니다. 클라우드 환경에 넣은 키가 Render로 자동 복사되지는 않습니다. 키를 GitHub나 채팅에 붙여 넣지 마세요.
4. 배포가 끝나면 Render가 발급한 **https://…onrender.com** 주소를 엽니다. 앱은 Render의 외부 주소를 자동 사용합니다. 별도 도메인을 연결하면 `APP_ORIGIN`에 해당 HTTPS 주소를 지정합니다.
5. Render 서비스의 **Environment**에서 자동 생성된 `SETUP_TOKEN` 값을 확인합니다. 앱의 첫 교사 계정 생성 화면에서 초기 설정 코드로 입력합니다. 교사 아이디와 비밀번호는 직접 정합니다.
6. 교사로 로그인해 모둠 계정을 만들고, 학생이 의뢰를 제출하면 교사 화면에서 **후보 3개 작성**을 누릅니다. 디자인 의뢰에서는 후보별 **시안 이미지 생성**도 사용할 수 있습니다. API 호출 비용은 OpenAI에서 별도로 부과합니다.
7. 교사가 결과를 선택하고 검토 확인 후 전송하면 학생 계정에서 결과를 볼 수 있습니다. 이후 Render 웹주소로 여러 기기에서 접속할 수 있습니다.

배포 버튼은 Render 설정 화면을 여는 링크입니다. 사용자 계정 연결·요금 확인·배포가 끝나기 전에는 실제 서비스 주소가 생성되지 않습니다. 이 저장소에 API 키나 운영 계정 비밀번호는 포함되지 않습니다. 이미지 모델 사용에는 계정에 따라 조직 인증·모델 권한이 필요할 수 있습니다.

## 외부 배포

정적 사이트 전용 호스팅으로는 실행할 수 없습니다. **Node.js 24.5 이상 서버와 영구 디스크**를 지원하는 호스팅 또는 VPS를 사용하세요. 현재 구조는 단일 서버 인스턴스용입니다.

1. 소스를 GitHub에 올리거나 서버에 복사합니다. 설치 명령은 `npm ci`, 시작 명령은 `npm start`입니다.
2. 영구 디스크를 마운트하고 `DB_PATH=/data/app.sqlite`처럼 해당 디스크의 경로를 지정합니다. 임시 디스크에 두면 재배포 때 학생 기록이 사라질 수 있습니다.
3. `NODE_ENV=production`, 실제 HTTPS 주소인 `APP_ORIGIN`, 충분히 긴 무작위 `SETUP_TOKEN`을 설정합니다. 필요하면 `AI_API_KEY`를 추가합니다. 비밀 값은 호스팅 서비스의 비밀 환경 변수에 입력합니다.
4. HTTPS를 활성화한 뒤 배포 주소에서 첫 교사 계정을 생성합니다. 초기 설정 화면에 SETUP_TOKEN 값을 입력합니다. production의 세션 쿠키는 Secure이므로 HTTPS가 필요합니다.
5. 상태 확인 경로는 `/api/health`입니다. 첫 계정 생성 후 학생 제출 → 교사 검토 → 결과 확인 흐름으로 검증하세요.
6. 데이터베이스와 이미지 파일을 백업하고, 공개 배포 전에 학교의 학생 데이터 보관·운영 정책을 정하세요.

Dockerfile도 포함되어 있습니다. Docker 빌드와 외부 호스팅 배포는 이 환경에서 아직 검증하지 않았습니다.

```sh
docker build -t jeju-startup .
docker run --env-file /secure/path/jeju.env -p 3000:3000 -v jeju-data:/data jeju-startup
```

`/secure/path/jeju.env` 파일은 저장소 외부에 두고 위 표의 배포 변수를 설정합니다. TLS는 호스팅 서비스 또는 역방향 프록시에서 종료합니다. HTTPS 외부 주소와 APP_ORIGIN을 정확히 맞추세요.

## 데이터와 보안

계정·비밀번호 해시(scrypt)·8시간 세션·의뢰·후보·평가·선택 결과·코인 원장은 SQLite에 저장됩니다. 서버가 재시작되어도 유지됩니다. 세션은 HttpOnly/SameSite 쿠키로 전달하고 원문 세션 토큰 대신 해시를 데이터베이스에 저장합니다. 권한은 서버에서 검사하며 다른 모둠의 기록과 미공개 결과를 학생에게 보내지 않습니다.

데이터는 `data/` 아래에 생성되며 Git에서 제외됩니다. 안전한 백업 예시:

```sh
node --input-type=module -e "import {DatabaseSync,backup} from 'node:sqlite'; const db=new DatabaseSync(process.env.DB_PATH || 'data/app.sqlite'); await backup(db, '/secure/backup/app.sqlite'); db.close();"
```

생성 이미지가 있다면 DB_PATH와 같은 디렉터리의 `images/`도 함께 백업하세요. 백업 대상 디렉터리를 먼저 생성하고 접근을 제한하세요. SQLite 실행 중에는 원본 `.sqlite` 파일만 단순 복사하면 WAL에 있는 최신 변경을 놓칠 수 있습니다. 교사 계정 복구용 이메일 기능은 제공하지 않으므로 관리자 비밀번호를 안전하게 보관하세요. 개별 기록 삭제·보관 기한 자동화·대규모 다중 인스턴스 운영은 후속 개발 범위입니다.

## 검증

```sh
npm run check
npm test
```

기존 데이터와 분리된 임시 SQLite에서 계정 생성·인증, 권한 격리, 코인 차감과 동시 제출, 교사 생성·수정·선택 전송, 추가 요청, 일일 초기화, 기간 한도, 비밀번호 재설정, 계정 중지, 재시작 후 영속성을 검사합니다. Node 테스트 러너가 실제 HTTP 서버를 열므로 로컬 포트 사용 권한이 필요합니다.

실제 유료 AI API는 키가 없으면 검증되지 않습니다. 생성된 후보가 정확한지와 학생 수준에 적합한지는 교사가 확인해야 합니다.
